## 🎯 What I do

I take a messy, expensive problem and turn it into a working, measurable system. I'm aiming at AI engineering, with software engineering as the foundation under it.

## 🧠 How I work

1. **Start from the problem, not the tool.** I define who has the problem, what it costs them, and how we'll know it's fixed before I write code.
2. **Ship early, then iterate on real feedback.** I'd rather put a working version in front of real users than polish something nobody has tested.
3. **Measure everything.** Every project in my pinned repos states the problem, the approach, and the result in numbers.
4. **Learn whatever the problem needs.** I pick up new tools quickly because I understand the fundamentals underneath them: data structures and algorithms, math and statistics, how systems behave in production.

## 💼 Why I think about business, not just code

Before and alongside my CS education, I worked in B2C phone sales and content writing, and I've run real ventures myself. I understand customers, pricing, objections, and what actually makes a client pay. Most engineers learn this late, if ever, and it changes which problems I choose to solve.
